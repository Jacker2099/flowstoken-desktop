# FlowsToken 自主品牌与上游维护边界

FlowsToken 维护自己的产品版本、账户和计费接入、普通/智能/官方分组、官网模型目录、品牌资源、更新渠道、签名和发布流程。上游核心提供运行时、模型协议、工具、会话及通用桌面能力；不把上游产品决策自动视为 FlowsToken 的产品合同。

## 当前版本

当前已发布的 0.6.9 包含 0.6.4 阶段完成的 Open Vetta 0.5.60 完整同步。该次合并保留了 FlowsToken 叠加层，并恢复上游删减的 macOS 源码检查、安装与严格打包验收；这些保护在当前版本继续保留。已确认存在产品缺陷的源码进入仓库发布禁用记录，不允许仅凭旧公证票据恢复发布。

## 后续核心更新

可以按模块挑选安全修复、模型协议兼容、会话与工具执行修复及必要功能，无需每次完整合并上游 UI、账户服务或发布工作流。每项更新记录来源提交、受影响合同及验证证据；通用组件通过稳定接口接入产品层，保留收费组和用户配置的不变量。安全修复也要评估是否依赖其他提交，不能只复制单个补丁而遗漏前置变化。

上游更新须保留 FlowsToken 账户、计费组映射、自有更新源、凭据身份、历史数据及用户配置，不得移除我们的三平台源码检查、四平台安装和更新验收、签名或公证检查。重大协议和依赖变化先完成兼容性检查与迁移验证，再发布。保持上游核心与品牌层的边界，逐步收敛必要的相邻修改，不为易合并而删除功能或降低安全检查。

## 同步与发布权限

当前每日只读检查上游更新，`flowstoken-upstream-sync` 的自动合并、升版及发布流程保持手动停用，不因检查到新版本而自动启用。同步候选在独立分支准备，经过 PR 完整差异审查及既有 CI 门禁后再合并；这是维护流程要求，不代表已配置 GitHub 强制分支保护。固定合并规则和测试不能保证任意未来业务改动零风险，账户、计费、凭据和数据兼容仍须逐项审阅。

后续是否恢复自动同步或实施精选核心更新，应按当时用户的明确指令处理。最终发布另需明确授权，始终绑定确切源码 SHA、版本、构建与公证回执，并通过同一套严格门禁。具体入口见 [发布说明](RELEASE.md#上游更新检查与审核)。
