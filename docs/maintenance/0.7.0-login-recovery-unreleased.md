# FlowsToken 0.7.0 登录与凭据修复记录（未发布）

本批修复最初基于已公开的 0.6.9，后确定以 0.7.0 交付，使现有 0.6.9 客户端能够检测新版。版本事实源和对应 workspace lock 已调整；不覆盖 0.6.9 tag、历史发布说明或既有下载包。本文件记录候选源码与验收边界，不代表已部署、已公证或已发布。

## 最终实现范围

- 一键登录改由系统默认浏览器授权。网页已登录时确认当前账户，未登录时先网页登录并保留安全回跳；网页原会话不退出，客户端使用独立会话。
- 桌面使用 PKCE S256、随机 state、一次性 loopback 回调和 HTTPS 兑换；授权码有效期 60 秒，整体授权等待上限 5 分钟。重复点击合并，取消、退出和换号阻止迟到结果恢复旧身份。
- 兑换先进入独立 staging Session；严格校验唯一的官方 host-only、固定路径、Secure/HttpOnly/SameSite=Strict refresh Cookie 后，串行导入正式分区并提交认证。失败按认证代际回滚，不覆盖新账户；正式认证请求等待 Cookie 事务完成。外部浏览器的 Cookie、密码及用户 profile 不被读取。
- 官方分组密钥只保留在当前认证会话内存。启动、模型设置和目录同步读取元数据，不提前解密或迁移无关自定义凭据；旧引用、密文、配置和历史保留。显式自定义密钥操作仍受系统安全存储保护，失败回滚保留原密文。
- 429、5xx 和短暂网络错误不再误判退出。遵守 Session 冷却并合并请求；暂时分组同步失败累计最多 3 次尝试，首次失败后至多自动重试 2 次，间隔至少 60、120 秒并尊重更长的 `Retry-After`。权限/本地写入错误及重试耗尽不持续自动重试，账户设置保留显式同步入口。
- 聊天、后台任务和 CLI/Claw 共用当前账户与计费分组授权约束；托管 key 跨进程仅走已认证本机通道，不能因并发或换号落到其它计费组。
- 远程配对状态与邀请展示不访问钥匙串，未知可用性不误报不可用；首次创建配对仍由用户操作并强制加密。插件缺失密钥读取不再触发无意义的安全存储探测。
- 新安装和未选择主题时默认浅色，首次显示与原生窗口一致；保留已有明确深色或跟随系统选择。登录后的可选欢迎引导不要求手工重复配置官方 key。
- macOS 安装器交接使用 FlowsToken 应用身份；自定义服务商重命名保留凭据、认证头、默认模型及并发目录更新。实际旧版安装升级仍需单独验收。

设计、协议边界及兼容取舍见 [ADR-0146](../adr/0146-flowstoken-session-credentials-and-login-recovery.md)，客户可见草稿见 [0.7.0 发布说明](../../.github/release-notes/v0.7.0.md)。

## 钥匙串与用户数据边界

普通官方账户登录及模型元数据初始化不需要访问旧 `vetta Safe Storage`。这不承诺全应用永久没有系统授权框：显式读取/保存自定义 key、真正配对或使用 SSH/插件等凭据时，仍受 macOS 保护。已有密文的系统访问控制不能由客户端代替用户授予。

不修改真实已安装应用、真实 `.vetta` 或浏览器账户。保留正式 Chromium 登录分区和已有明文自定义配置的兼容读取；本批元数据更新不新增明文密钥，也不以重置 profile 解决登录问题。
