# ADR-0145：FlowsToken 模型目录与计费身份分离

## 状态

已接受；随 FlowsToken 0.6.4 实现并验收。

## 背景

模型上线、下架、改名、厂商排序和分组调整是运营数据，不应要求重新分发桌面安装包。原目录虽能更新三个已有组的模型，却把可用分组、令牌名称和部分展示顺序固定在客户端。两个独立模型菜单也容易出现展示漂移。

公开目录可以决定如何展示模型，但不能授予账户权限、改变已保存会话的计费组、下发密钥或可执行代码。已打开会话还可能持有旧 Model 对象，仅更新菜单或 Registry 不足以阻止下架后继续调用。

## 决策

- 官网和客户端模型展示消费同一份 `/api/pricing`、厂商、发布时间及运营配置生成的目录；价格数值和账户权限继续由 NewAPI 的原接口负责。
- 新增 `desktop-catalog-v2.json`，与 schema1 端点并存。schema2 支持动态组、厂商、模型及已编译支持的能力和推理级别；不包含任意 API 地址、凭据、脚本或 CSS。
- `group.id` 是不可变的 NewAPI 计费组 key。标题及本地化标题可更新；真实计费 key 变更视为停用旧组和新增新组。客户端共享纯函数派生 provider ID，保留三个旧 ID 与普通组 legacy 别名，拒绝远程重绑。
- 目录合法快照整体应用；失败保留最后有效版本。版本与内容 revision 用于追踪，不要求时间单调，允许明确运营回滚。网络、磁盘缓存和默认兜底来源可区分。
- 账户服务只对目录组与认证 `/api/user/self/groups` 的交集准备令牌，核对真实 token 的 group/status/归属。令牌名称由稳定组 ID 生成并满足服务端长度限制；标题变更不重复建令牌。
- 所有 provider 更新进入已有 ModelSettings mutationQueue，在队列中读取最新配置、合并数据、检查账户代际并提交。提交期间换号时回滚自己的更新，不覆盖排队的下一账户或用户修改。
- Coding Agent 模型运行时提供可选的访问校验 hook 和访问 lease，Desktop 注入目录、认证权限与受管密钥绑定检查；取凭据前和异步返回后均验证代际。其他宿主无 hook 时维持既有行为。
- 下架只移除新选择项，不删除会话或静默切换收费组。旧选择再次调用时得到结构化、可恢复的不可用错误，由用户明确选择新模型。
- 聊天、设置、团队与任务选择器复用一个纯展示组件；宿主提供目录派生 props，View 不调用 IPC。组切换、带 logo 厂商导航、搜索、紧凑模型行与推荐均跟随数据。
- 客户端前台和持续开启时按一分钟间隔重校验，打开菜单与恢复前台也重校验，手动刷新支持强制更新。并发请求去重，不因重新渲染重复准备账户令牌。

## 兼容与边界

旧安装包继续读取 schema1，新的 schema2 请求仅在 v2 端点不存在时降级到 v1。合法空目录代表下线，不能被默认目录补回。个人 BYOK provider 和显式模型参数保留；普通文本模型不会接收图片输入，图像生成、embedding、rerank 与音视频不会混入聊天模型列表。

新本地能力、新网络协议、新权限及安全更新仍需要桌面发版。目录数据变化无需发版；根许可证、第三方 NOTICE、品牌、账户和严格发布门禁分别维护，不由上游 UI 或流程更新自动覆盖。

## 验收

- 新增/删除/改名/排序分组，新增/下架模型，修改厂商 logo、默认推荐与能力时，只替换服务端配置，客户端无需重启或重新安装。
- 目录无效、断网、配置发布中断与回滚不产生半更新；v1/v2 来自同一生成批次。
- 退出/换号落在 cookie 读取、请求、快照、配置队列、文件写入、Registry 刷新和取密钥间隙时，不发送或返回旧账户凭据，不发布过期状态。
- 当前会话下架模型、权限收回、旧缓存 Model、普通组 legacy ID 与新动态 provider 均使用同一访问检查，不跨收费组自动回退。
- 真实三平台源码测试、平台适用的 SSH 合同、四平台签名安装与严格更新验收全部通过后才提交正式发布；公证申请与产品源码、应用签名和字节保持可追溯。
