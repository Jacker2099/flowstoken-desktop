# ADR-0146：FlowsToken 会话凭据与可恢复登录

## 状态

0.7.0 候选源码已实现，正在统一验收，尚未部署配套网站服务、提交公证或发布。修复最初基于已公开的 0.6.9，现已选择 0.7.0 作为新版本，使 0.6.9 客户端能够检测到更新；不覆盖既有 tag、发布说明或安装包。执行状态见 [0.7.0 维护记录](../maintenance/0.7.0-login-recovery-unreleased.md)。

## 背景

官方账号登录后的分组密钥原本写入通用 Electron safeStorage 保险库。共享的 `vetta` 安全存储身份可能要求 macOS 授权。拒绝后，读取被当成缺失，登录、账户快照与 Renderer 多处重复补齐；刷新接口的 429 又被当成认证失败。凭据写入失败的回滚还可能把不可解密的旧记录当成不存在而删除。

直接更名 `APP_RUNTIME_NAME` 会改变旧密文的解密身份。修复需要保留历史配置和密文，也不能替用户授予系统权限、关闭加密或把官方密钥明文落盘。网页登录会话还需要与客户端会话分开，使已有网页登录能直接授权客户端使用。

## 决策

### 系统浏览器授权与会话提交

- 一键登录使用系统默认浏览器打开 `/auth/desktop`。网页已有会话时显示当前账户并确认授权；未登录时先网页登录，再安全返回同一授权请求。网页原会话保持登录，客户端不读取外部浏览器的 Cookie、密码或用户配置。
- 客户端生成随机 `state` 和 PKCE S256 校验材料，只监听 `127.0.0.1` 的随机非特权端口及固定 `/flowstoken/callback` 路径。回调严格检查 Host、方法、路径、state、参数和一次性消费。URL 只携带授权码或拒绝结果，不携带 access/refresh token。
- 网站签发的授权码有效期为 60 秒、单次使用，并绑定 client、回调和 PKCE challenge。客户端经 HTTPS 在独立、不持久化的 staging Session 中换取账户凭据。整个浏览器授权流程最多等待 5 分钟；重复点击共享同一流程，关闭客户端、退出、换号或明确取消都会使未提交结果失效。取消后不自动重新弹出授权。
- 只允许从本次 staging Session 导入唯一、非空、host-only `www.flowstoken.com` 的 `new_api_refresh` Cookie，路径必须为 `/api/user/auth`，且为 Secure、HttpOnly、SameSite=Strict。不导入浏览器会话，也不导入 staging 中的其它 Cookie。
- 正式账户 Cookie 的导入、回滚和退出清理串行执行；正式 Session 的认证请求等待该事务完成。异步等待前后检查取消和认证代际，再同步提交内存身份。失败时只移除仍属于本次操作的写入；仅当旧认证代际仍有效时恢复原 Cookie，不能在退出或换号后恢复旧账户。提交成功后不再由迟到的取消回滚已接受身份，staging 最终关闭连接并清理。
- 原有内嵌网页/账号密码兼容入口仍受其登录取消和超时规则约束；它不再是一键登录的主路径。系统浏览器授权依赖配套 NewAPI 授权、兑换接口及网页上线，不能仅发布客户端便宣称功能可用。

### 模型凭据与元数据

- 官方托管模型密钥只保留在主进程内存，绑定认证代际、账户、分组和 token ID。登录后通过已认证接口获取，退出和换号时清空，绝不回退到旧保险库。配置只保存目录、计费绑定与已有旧凭据引用；旧密文不读、不覆盖、不删除。
- `ModelSettingsService` 的 metadata/Renderer 读取不迁移无关旧明文、不解密自定义密钥。官方目录和绑定更新保留自定义配置、历史与显式模型参数；未修改的既有自定义明文保持原样，直到其主动使用或安全保存流程处理。
- 托管 provider 通过会话 resolver 取 key。用户显式替换为自定义 key 时使用独立的安全存储引用，不能覆盖原托管密文。显式读取自定义 provider 只解密目标记录；后台预设刷新仅用本次运行已成功读取/保存的缓存或既有明文，不为刷新主动打开钥匙串。
- CLI/Claw 通过已认证本机 RPC 的 `models.resolveCredential` 取用托管密钥。桌面宿主逐次核对本地绑定、目标地址、目录权限和异步等待前后的认证代际；共享协议包不包含桌面业务授权规则。请求仅允许 IP 字面量 loopback HTTP，不跟随跳转，有超时；响应不缓存、不记录、不落盘，也不经 argv 或环境变量传递。
- 同一账号和绑定可共享凭据身份；不同绑定或换号后的迟到响应不能恢复旧 key。聊天、后台任务与 CLI 保持账户、计费组和模型权限边界，不因不可用而自动换到另一收费组。已发出的远程模型请求无法在注销时追回。
- 通用保险库事务保存原密文字节作为恢复点，不可访问与不存在分别处理。安全存储在写入中途失效时仍能原样回滚。

### 有限恢复与后台查询

- 429 按 `Retry-After` 进入 Session 级冷却，缺失或无效时等待 60 秒；认证刷新合并并发请求。网络错误、5xx 保留最后已验证身份供界面显示，但不能以缓存身份跳过模型权限检查。真实认证失效仍清除对应身份。
- 分组密钥同步的暂时网络故障、429、5xx 可由后续正常快照/刷新自动重试。同一认证代际连续失败累计最多 3 次尝试：首次失败后至多再自动重试 2 次，基本等待为 60、120 秒，429 不早于服务器要求的时间。权限错误、本地配置或凭据写入错误不进入自动重试；耗尽后等待用户显式同步。成功会清除失败状态，手动重试或新的认证代际可重新开始。
- 远程配对状态与已有邀请投影只读取内存，不探测或解密钥匙串。Desktop IPC 的 `vaultAvailable: null` 表示尚未主动检查，不表示授权或不可用；首次创建配对由已有按钮触发，实际创建仍严格检查并加密，成功后的续码行为保留。LAN/手机协议不改变。
- 插件读取不存在的密钥先检查记录是否存在，再决定是否访问安全存储；已有密钥继续遵守原安全检查。真正使用自定义密钥、手机配对、SSH 或插件密钥仍受系统权限约束。

### 首次体验

新安装及没有明确主题偏好的客户端默认浅色，HTML 首帧、Renderer 与原生窗口在显示前对齐。保留用户已保存的深色或跟随系统选择；无法区分来源的旧 `dark` 值也不覆盖。登录后的首次语言外观、可选权限和欢迎引导可以跳过，不要求重复配置官方模型 key，也不自动授予系统权限。

## 兼容和边界

保留应用运行身份、`.vetta`、既有 Chromium 正式登录分区、历史和自定义配置。重启后，官方密钥由有效登录会话重新获取；离线时不能用旧磁盘密钥继续官方模型请求。

“正常官方登录与模型元数据初始化无需访问旧 safeStorage”不等于整个应用永不出现系统授权。自定义密钥首次显式使用或保存，以及已启用功能真正使用其凭据时，仍可能需要 macOS 许可。本实现不代替用户修改钥匙串 ACL。

0.6.9 已发布制品不会自动获得源码变更。候选安装、真实旧版升级和系统权限行为须在隔离 Mac 用户或虚拟机中验收；不能用当前真实用户的 `.vetta` 路径运行会清理 profile 的旧升级脚本。公证、部署和发布状态单独记录，源码或测试通过不代表已完成交付。

## 验证

定向测试覆盖真实内部服务装配、元数据读取零 crypto、拒绝解密与密文回滚、有限重试与冷却、认证代际/取消/并发、staging Cookie 提交和回滚、CLI/Claw 授权以及 Renderer 操作。网络、Electron 和加密替身仅用于外部边界，使用临时配置及虚构凭据，不调用付费模型。

原生验收使用新构建的 Electron、隔离 profile 和受限网络 fixture，并严格断言启动与官方登录路径零 safeStorage 调用、无未处理异常、旧密文/自定义配置保留；这不代替真实网站、签名安装包或旧版升级验收。最终构建及原生多轮结果由本轮统一验收补录到维护记录。
